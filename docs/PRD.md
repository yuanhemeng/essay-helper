# ScholarFlow 产品需求文档 v0.1

## 1. 产品定位

ScholarFlow 面向需要长期阅读、整理、写作和投稿的研究者，把“文献理解”和“论文产出”放在同一个工作台中。核心原则是：AI 的每个结论都尽可能回链到论文原文，用户的批注、词库、研究树和写作内容都可以沉淀为个人知识资产。

## 2. 目标用户

- 研究生、博士生和高校教师
- 需要高频阅读英文论文的研究者
- 需要整理文献综述、构建研究框架并准备投稿的作者

## 3. 核心工作流

1. 导入 PDF，自动提取元数据、目录、正文、表格、参考文献和术语。
2. 在阅读器中进行页码跳转、缩放、文本选择、高亮和批注。
3. 通过 AI 解释、翻译、总结和追问，并且看到回答引用的页码和原文片段。
4. 将论文加入分类，自动发现论文之间的主题、方法和引用关系。
5. 把正在写作的论文设为研究树主干，从节点扩展论点、证据和推荐文献。
6. 根据研究主题和稿件状态推荐期刊，解析投稿指南并生成准备清单。

## 4. MVP 范围

### P0：必须完成

- 用户本地登录与工作区
- PDF 上传、文件管理和基础 PDF 阅读
- 目录解析、页码跳转、缩放、文本选择
- 高亮、批注、批注列表和原文定位
- 基于当前论文的 AI 问答、段落翻译、章节总结
- 回答引用页码和原文证据
- 文献标签、分类、搜索

### P1：第二阶段

- 个人专业词库：术语、用户偏好译法、定义、例句和版本记录
- 多论文检索和相似文献推荐
- 论文关系图：主题、方法、作者、引用和时间线
- 研究树：主干论文、章节节点、论点、证据和待补文献
- 写作区：大纲、段落生成、引用插入和参考文献管理

### P2：第三阶段

- 期刊推荐和投稿指南解析
- 投稿要求变更监测
- Cover Letter、摘要和格式检查
- 逐项投稿准备工作流
- 导出 Word、LaTeX、BibTeX、Markdown 和 CSL JSON

## 5. AI 能力边界

AI 输出需要分为三类：

- **有证据回答**：必须附带论文、页码和原文片段。
- **基于用户知识库的推断**：明确标注“推断”，列出使用的文献。
- **开放推荐**：明确标注推荐依据、时间和数据来源。

不应默认声称论文结论、引用信息或投稿要求是准确的；用户需要可以查看原文、修正术语和反馈答案。

## 6. 关键数据模型

- `Document`：文件、标题、作者、年份、期刊、解析状态、标签
- `Page`：页码、文本、版面块、图片和表格
- `Annotation`：类型、高亮范围、页码、评论、颜色、创建时间
- `Conversation`：上下文文献、消息、引用证据
- `Term`：术语、首选翻译、定义、领域、来源和用户修正
- `ResearchNode`：节点类型、父节点、论点、状态、关联文献
- `Journal`：期刊元数据、主题匹配、投稿要求和来源时间

## 7. 推荐技术路线

### 前端

- React + TypeScript + Vite
- PDF.js 负责 PDF 渲染和文本层
- Zustand 或 TanStack Query 管理工作区状态
- 统一的引用证据、批注和搜索组件

### 后端

- Python FastAPI
- PostgreSQL 保存结构化数据
- 对象存储保存原始 PDF
- Redis + Celery/RQ 运行解析任务
- pgvector 或专用向量数据库做语义检索

### AI 管线

1. PDF 版面解析和 OCR
2. 章节、段落、表格和参考文献结构化
3. 分块、嵌入和索引
4. 检索增强问答
5. 引用证据校验
6. 用户反馈写回术语和检索偏好

## 8. 验收标准

- 导入一篇英文 PDF 后，5 分钟内可以阅读、搜索和定位章节。
- AI 对当前页面的回答至少返回一个可点击的页码证据。
- 高亮和批注在刷新后仍然存在，并能从批注跳回原文。
- 用户修正过的专业术语在后续翻译中优先使用。
- 研究树节点可以关联文献、生成扩展问题并回写到写作大纲。
- 投稿要求显示来源和抓取时间，不能只展示未经核验的模型总结。
